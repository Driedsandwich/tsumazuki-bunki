# つまずき分岐

生徒の誤答を式で再現し、原因の候補を見分ける一問を出す、個別指導の講師向けの Web アプリです。

- 公開デモ：<https://tsumazuki-bunki.vercel.app>（2026-11-06 時点で実 AI に接続した構成）
- 東京AIハッカソン 2026 のために作りました。
- AI の鍵（API キー）がなくても、手元では見本の応答（mock）で最後まで動きます。動かし方は下の節にあります。
- ライセンス：MIT（[LICENSE](LICENSE)）。見本の SVG に使ったフォントは `public/samples/FONT-LICENSE.txt` の条件に従います。

名前の案：**つまずき分岐**（採用）／**次の一問**／**まちがいの分かれ道**。

個別指導の講師向けに、生徒の誤答を再現し、原因の候補が分かれる一問を出す Web アプリです。中学 1 年の一次方程式に絞っています。「AI に説明を頼む」ことを診断には使いません。

## まず動かす

Node.js 22.12 以上（検証：22.23.4）、npm を用意します。

```sh
npm ci
npm run dev
```

表示されたローカル URL を開きます。環境変数なしでは mock。**見本 ②「同じ誤答、違う原因」**を押すと、書き起こしの確認、2 候補、見分ける一問、戻る単元、確認 3 問まで体験できます。「見本の返答を入れる」は合成生徒の返答を入れる体験専用ボタンです。

新しい答案は「問題の式」「生徒の途中式」に直接入力してください。mock でも入力ごとに解析・再現・問題探索を行います。見本の ID によって診断結果を選んでいるわけではありません。

```text
問題：7x + 5 = 26
途中式：
7x = 31
x = 31/7
```

これを入れると、移項の符号を変えない規則で再現されます。`2x=10` → `x=123` は「特定できない」、`0.5x+1=3` → `x=4` は「同値が保たれています」です。

```sh
npm test
npm run eval
npm run build
```

`build` は型検査、Vite のブラウザ用ビルド、**esbuild による api/analyze.js 1 本の生成**を行います。`npm run preview` は静的ビルドの見た目の確認用です（AI 関数は起動しません）。mock 見本・手入力は preview でも使用できます。ローカルで関数も使う場合は `npm run dev` を使います。

## AI とコードと人の分担

| 処理                           | 担当        | 守っている境界                                                                   |
| ------------------------------ | ----------- | -------------------------------------------------------------------------------- |
| 画像の各行を書き起こす         | 画像対応 AI | 式・読めない印・0〜1 の確からしさだけ。計算・修正・原因決定をさせない            |
| 発言から規則 ID と引用を挙げる | AI          | 原文の連続引用であることをコードで検査。候補を追加する権限はない                 |
| 読み違いを直す                 | 講師        | 全行を編集可能。「確認しました」をチェックしてから診断                           |
| 式の構文解析・同値判定         | コード      | 自前の再帰下降パーサと BigInt 有理数。eval や浮動小数の近似比較を使わない        |
| 最初に崩れた行を特定           | コード      | 問題 → 各行を順番に検証                                                          |
| 誤答の再現・候補の列挙         | コード      | 直前の式に 9 規則をそれぞれ 1 回適用して照合                                     |
| 発言の候補を残す               | コード      | 式で再現でき、引用も原文にある場合だけ証拠に添付。発言で他の候補を消さない       |
| 候補を見分ける一問             | コード      | 問題の族のパラメータを探索。各規則の答えと正答が全て異なる小整数であることを検証 |
| 追加の答えで候補を減らす       | コード      | 一致しない候補を除外。最大 2 回。正答やどの予測とも違う答えなら断定しない        |
| 戻る単元・声掛け               | 固定データ  | 規則に対応した単元と、あらかじめ書いた一言                                       |
| 確認問題 3 問・採点            | コード      | 対象単元の問題を生成し、有理数で答えを計算                                       |

AI の confidence は書き起こしへの確からしさです。生徒の原因の確率や、コードの診断精度ではありません。

## 診断の具体的な意味

式を `ax+b=cx+d` の線形係数にまとめ、解集合（解一つ／すべての x／解なし）を比較します。係数は分数・有限小数を正確に扱います。入力中の `x/3`、`(2x+1)/3`、`2(x-3)`、全角数字・全角 x・`× ÷ −` に対応します。分子が複数項の分数は必ず `(x+1)/3` と書きます。

最初の不一致の直前に規則を 1 回当て、**生成した等式と生徒の次の行の解が同じ**なら候補にします。途中の正しい計算が省略された `x=数` だけの答案も照合できます。文字列の見た目が同じであることまでは要求しません。生成式と生徒の式を画面で並べ、どこまで検証したかを明示します。

この比較は「その考え方だった」と証明するものではありません。同じ解になる別操作、偶然同じ答えになった計算ミスもあり得ます。出力は一貫して**指導のための仮説**です。

### 9 つの規則

| ID                   | 名前                           | 適用例                  | 戻る単元                   |
| -------------------- | ------------------------------ | ----------------------- | -------------------------- |
| move-sign            | 移項しても符号がそのまま       | 3x+4=19 → 3x=19+4       | 等式の性質                 |
| distribute-tail      | かっこの後ろに掛け忘れる       | 3(x+2)=18 → 3x+2=18     | 分配法則                   |
| minus-tail           | かっこの後ろでマイナスを落とす | −2(x+3)=8 → −2x+6=8     | 分配法則                   |
| negative-product     | 負 × 負を負にする              | (−2)×(−3)×x=18 → −6x=18 | 正負の数の乗除             |
| divide-sign          | 割る係数のマイナスを落とす     | −4x=20 → x=5            | 正負の数の乗除             |
| subtract-coefficient | 係数で割らずに引く             | 3x=12 → x=9             | 等式の性質                 |
| denominator-constant | 分母を払うとき定数を忘れる     | x/3+2=6 → x+2=18        | 分数・小数を含む一次方程式 |
| unlike-terms         | x の項と数だけの項をまとめる   | 2x+3=20 → 5x=20         | 同類項                     |
| like-sign            | 同類項の係数で符号を落とす     | 5x−2x=12 → 7x=12        | 同類項                     |

規則は適用できる位置ごとに変換後の式を決定的に返します。恒等変形になるものは誤り候補から除きます。移項は通常の整理方向（左の定数項を右へ／右の x 項を左へ）を扱います。分母払いは、分母の最小公倍数を全項に掛ける際に、最上位の加減で独立している整数の定数項一つを掛け忘れるモデルです。負の分配は外の負の数の大きさは掛け、後ろの項だけ符号を落とします。

### 見分ける一問

`a(x+b)=c`、`ax+b=c`、`ax=c`、`x/a+b=c`、`ax+bx=c`、負数の積を含む式の 6 族を使います。`a` は −2, −3, −4, −1, 2, 3, 4、`b` は 2, 3, 4, 1, −2, −3、`c` は −18〜18 の偶数を探索します。

各候補の規則を実際に適用して解き、規則内で複数の異なる予測が出る問題を除きます。残った規則の予測と正答が **全て異なり、−20〜20 の整数**になるものだけ出します。初回の見本 ②では `−2(x+2)=−18` が見つかり、後ろの掛け忘れは `x=10`、後ろのマイナス落ちは `x=11`、正答は `x=7` に分かれます。

全候補を一問で分ける条件なので、見つかった場合は通常 1 回で絞れます。安全上の上限を 2 回にしています。問題族の中に識別問題がない場合は**特定できない**として引き継ぎます。任意の候補の組に対して識別問題が必ず存在する保証はありません。

## AI の接続

環境変数を実行環境に設定します。鍵の値をソース、README、設定例ファイルに書かない設計です。`.env.example` は作っていません。ブラウザへ鍵を渡す `VITE_` 変数も使いません。

| 変数              | 意味                                                                 |
| ----------------- | -------------------------------------------------------------------- |
| AI_PROVIDER       | 未指定または `mock` は無料の見本。`openai` で互換 API を使用         |
| AI_API_KEY        | 外部 AI の秘密鍵。サーバーのみ                                       |
| AI_MODEL          | 利用する画像対応モデルの名前。必須                                   |
| AI_BASE_URL       | OpenAI 互換の HTTPS ベース URL。省略時は `https://api.openai.com/v1` |
| RATE_LIMIT_SECRET | 実 AI 利用時に必須。32 文字以上のランダムな署名用秘密値              |
| RATE_LIMIT_MAX    | 署名 Cookie による 1 分の読み取り要求上限。既定 8、1〜30             |
| IP_RATE_MAX       | 同じ接続元の 10 分の読み取り要求上限。既定 60                        |

`POST {base}/chat/completions`、`response_format: {type: "json_object"}`、画像は `image_url.url` の data URL を使います。互換提供者はこの形式と画像入力に対応している必要があります。モデル名と鍵は環境によって変わるため固定しません。

JSON は行数・文字数・型・confidence の範囲・規則 ID・引用の原文一致まで検査します。JSON またはスキーマが不正なときにだけ、**同じ診断要求内で 1 回だけ取り直し**ます。接続エラー・HTTP エラーは再送しません。クライアントも自動再送しません。1 診断の読み取り要求は 1 回、外部 AI 呼び出しは最大 2 回です。入力画面に戻っても読み取り済みなら手入力で続行します。失敗時は手入力に戻し、診断エンジンはそのまま使えます。

外部呼び出しは 1 回あたり最長 23 秒、全体 48 秒の締切、ブラウザ 53 秒、Vercel 関数 60 秒です。

回数制限は署名 Cookie と関数実体内の接続元カウンターです。接続元は HMAC でハッシュ化し、画像・答案をカウンターに入れません。Cookie 削除、複数インスタンス、関数の再起動をまたいだ厳密な課金上限は保証しません。実 AI を公開する場合、提供者側でも予算上限を設定してください。

### Vercel で公開する

このフォルダを独立した Git repo として Vercel に接続し、Framework Preset は Vite、Build Command は `npm run build`、Output Directory は `dist`、Node は 22 系に設定します。`vercel.json` も同梱しています。環境変数なしで mock と手入力による全工程が動きます。

`api/analyze.js` は生成物を同梱し、ビルドでも再生成するため、デプロイ前の関数検出にも対応します。ルートをこのフォルダにしてください。

公開デモは冒頭の URL にあります。自分で公開した場合は、ログインしていないブラウザ／スマホから公開 URL を開き、下記の台本で確認してください。実 AI 接続を使う場合は設定後に新しい写真でも確認が必要です。

## 記録とプライバシー

名前欄、アカウント、データベース、解析 SDK、答案履歴の永続保存はありません。画像と答案は画面のメモリで扱い、アプリのサーバーには保存・ログ出力しません。画像はブラウザで最大辺 1600 px の JPEG に描画し直し、写真メタデータを除いてから送ります。

mock 見本・AI を使わない手入力はブラウザ内で完結します。実 AI の読み取りでは画像／途中式／任意の発言を設定した外部提供者へ送ります。提供者側の保持はそのサービスの条件に従うことを画面にも表示しています。アプリが提供者の保持を無効化したと保証するものではありません。

## 範囲と限界

- x 一つの一次式。括弧・分数・有限小数に対応。未知数を含む分母、二次式、方程式以外の答案行、文章題の意味は扱いません。
- 1 行 240 文字、答案 20 行、式のトークン 120 個、ネスト 24、有理数の分子・分母は各 100 桁までです。写真は JPEG / PNG / WebP、選択時 12 MB、送信 data URL 3.5 MB まで。HEIC は未対応です。
- 1 回の誤操作を想定します。複数の誤りの組み合わせや登録外の規則は十分に扱えません。無理に原因を作らず、講師に引き継ぎます。
- 未変形の途中式が残っていれば、すべて同値でも「完答」とは判定しません。問題への最終的な解答の妥当性は講師が確認します。
- サーバーに答案を残さないため、再読込後の復元、診断履歴、複数生徒の管理、アカウント機能は未実装です（今回の範囲外）。
- 見た目はスマホの操作性を優先した暫定デザイン。画面を Input / Review / Diagnosis / Result に分け、後からデザインを差し替えやすくしています。

## 実AIでの評価（2026-11-06・作者の手元で実施）

- 接続先：AI&（OpenAI 互換の口）の moonshotai/kimi-k3.1-pro。公開デモと同じ構成です。
- 規則を先に決めた架空の手書き風答案 23 枚：書き起こしは 23 枚とも合い、診断は全て正しい規則に絞りました（誤った断定 0）。1 回あたり約 1.07 円・約 1.9 秒。
- 比べ：AI に 9 つの規則を渡して選ばせる方式でも 23/23 で、精度の差はありませんでした。この作品の違いは、2 つの規則で答えが同じになる答案（23 枚中 3 枚）を、見分ける次の一問で確かめる所にあります。
- 限界：実際の生徒の答案では試していません。
