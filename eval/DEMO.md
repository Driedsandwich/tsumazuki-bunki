# 一次審査での体験台本（約 3 分）

## 1. AI とコードの境界を見る（約 30 秒）

1. URL を開き、右上の「鍵なし · mock」を確認。
2. 見本 ②「同じ誤答、違う原因」を選ぶ。
3. 画像の `-(x+3)=5 → -x+3=5` と書き起こしを見比べる。各行を自由に直せる。
4. 「問題と全行を見て…」にチェックし、「この途中式をコードで確かめる」を押す。

ここまでの mock は書き起こしだけ。以降は実際の式解析と計算。画像や見本 ID をキーに診断を決めていない。

## 2. 同じ誤答から見分ける（約 60 秒）

1. 最初に崩れた行と 2 候補が出る。「後ろの掛け忘れ」と「後ろのマイナス落ち」。
2. 各候補を開くと、コードが規則で生成した式を確認できる。
3. 次の一問 `-2(x+(2))=-18` を見る。「講師用：この問題で分かれる理由」を開くと、予測が `10 / 11 / 正答 7` と全て異なる。
4. 生徒が `11` と答えたとして入力する（「見本の返答を入れる」でもよい）。
5. マイナス落ちの規則だけが残る。戻る単元・固定の声掛け・単元のつながりを確認。
6. 確認 3 問に `1`、`2`、`3` を入れて「確かめる」を各問で押す。「3 問とも一致しました」が出る。

正答 `7` や予測外の `999` を入れた場合は、どちらの誤り方も確認できないとして「特定できない」になる。正答を無理に誤りへ分類しない。

## 3. その場の新しい入力を見る（約 60 秒）

「別の答案を試す」から、見本にない問題と答案を入力する。

```text
問題：7x+5=26
生徒の途中式：
7x=31
x=31/7
```

確認後、移項の規則で再現される。元の問題の正解は `x=3` だが、誤った答案の解は `31/7`。浮動小数に丸めず有理数で比較している。

次に `2x=10 → x=123` を入れると「特定できない」。`0.5x+1=3 → x=4` は同値で、誤った原因を出さない。

## 他の見本の結論と確認問題の答え

| 見本                 | 結論                                         | 確認 3 問の答え     |
| -------------------- | -------------------------------------------- | ------------------- |
| ① 移項の符号         | 移項しても符号がそのまま                     | 4、5、6             |
| ② 同じ誤答、違う原因 | 追加問に 11 → かっこの後ろでマイナスを落とす | 1、2、3             |
| ③ 負の係数で割る     | 割る係数のマイナスを落とす                   | −4、−5、−6          |
| ④ 分母を払う         | 分母を払うとき定数を忘れる                   | 4、9、16            |
| ⑤ x と数をまとめる   | x の項と数だけの項をまとめる                 | 3、3、3（x の係数） |

## 実 AI 接続後の新しい写真（未確認）

1. サーバーに AI の環境変数を設定して再デプロイ。右上が「AI 読み取り接続」になる。
2. 上の問題と誤答を紙に書いて撮影する。名前は写さない。
3. 問題の式を入力し、写真を選ぶ。任意で「移項したから」と生徒の言葉を入力。
4. AI の書き起こしと写真を照合。低い confidence や `?` を直す。
5. 診断後、発言の引用はコードの再現を通った規則だけに表示される。
6. 読み取り失敗時は、手入力で同じ診断の終わりまで進む。

外部 AI の実接続と新しい手書き写真による OCR は、この版では未確認。mock は新しい写真を読み取ったふりをせず、手入力へ案内する。
